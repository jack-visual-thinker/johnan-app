# ウェブサイト公開先 比較レポート（ざっくり網羅版）

作成日: 2026-10-27 / 対象: `johnan-app`（Next.js製、AIを使った開発で作成）

> 確認状況: 公式ドキュメントで確認できた数値には【公式】を付けています。第三者サイトの情報だけで確認したものは【要確認】です。ChatGPT（Codex）での相互ファクトチェックはまだ行っていません（末尾の「付録」を参照）。

---

## 1. 結論（先に）

| 用途 | おすすめ |
|---|---|
| AIで作ったサイトをそのまま、安全・低コストで公開したい | **Cloudflare（Workers 静的アセット）** ← 第一候補 |
| 社内の担当者がブログやお知らせを更新する必要がある | Cloudflare公開 ＋ **記事を管理する仕組み**（ヘッドレスCMS：microCMS など／WordPressを記事管理だけに使う） |
| 既存のWordPressサーバーをどうしても使いたい | 静的HTMLに書き出して**サブディレクトリに置く**（可能だが制約あり） |
| すでにVercel向けの設定がある | Vercelも使えるが、**会社のサイトは有料のProプランが必要** |

**理由**
- `johnan-app` にはすでにCloudflare向けの設定（vinext / wrangler）が入っているので、すぐに公開できます。
- 静的なファイル（HTML・画像など）へのアクセスは、無料プランでも**無料・回数無制限**です【公式】。
- 公開側でPHPが動かないので、ご懸念のPHPやWordPressプラグイン由来の攻撃を、仕組みとして受けにくくなります。

---

## 2. 背景：WordPress（PHP）のセキュリティ状況

- Patchstack（WordPressのセキュリティ企業）によると、2025年にWordPress関連で新たに見つかった脆弱性は**11,334件**で、前年比**+42%**でした。そのうち**91%がプラグイン**、9%がテーマで、WordPress本体（コア）はごくわずかです。
- 第三者サイトの引用では、次のような数字も紹介されています【要確認】。
  - よく狙われる脆弱性は、公開から**約5時間**で大量の攻撃が始まる。
  - 公開された時点で修正版がない脆弱性が**46%**ある。
- つまり、**リスクの中心はWordPress本体ではなく、プラグインと更新の遅れ**です。WordPressを使い続けるなら、プラグインを最小限にし、自動更新とWAF（不正アクセスを遮断する仕組み）を入れることが前提になります。

## 3. 選択肢ごとの比較

### A. 既存のWordPress（レンタルサーバー）を使う

AIで作ったサイトを載せる方法は3つあります。

| 方法 | 内容 | 評価 |
|---|---|---|
| A-1 サブディレクトリに配置 | Next.jsを静的HTMLに書き出し、`/vision/` などのフォルダにアップロードする | ◯ 可能。PHPは使わないので、この部分自体は安全。ただしサーバー全体のリスクはWordPress次第 |
| A-2 WordPressの固定ページに埋め込む | テーマやHTMLブロックに入れ込む | △ ReactやTailwindのCSSがテーマとぶつかりやすく、手間に見合わない |
| A-3 ヘッドレス（記事管理だけWordPress） | WordPressは記事の管理画面だけに使い、表示はCloudflareなど別の場所で行う | ◯ 更新しやすさと安全性を両立。ただしWordPressの保守は残る |

- **メリット**
  - 既存の契約やドメインをそのまま使える。
  - 社内の人がすでに操作に慣れている。
  - 追加費用がほとんどかからない。
- **デメリット**
  - サーバー上でPHPが動き続けるので、上に書いたプラグインのリスクは残る。
  - このサイトをレンタルサーバーに置くには、静的HTMLへの書き出しが必要。サーバー側で動く機能（Cloudflare Workersの処理など）は使えない。
  - 表示速度やCDN（世界中から速く配信する仕組み）はサーバー次第になる。
  - 補足：Simply Staticなどのプラグインで**WordPressのサイト自体を静的HTMLにして公開**する方法もある。管理画面は公開しない形にできるので安全性は大きく上がるが、フォームやコメントなどPHPが必要な機能は使えなくなる。

### B. Cloudflare（Workers 静的アセット／Pages）★推奨

- **費用**【公式】
  - 静的なファイルへのアクセスは無料・無制限。
  - サーバー側の処理（Functions/Workers）は、無料プランで1日10万リクエスト、1回あたりCPU時間10ミリ秒まで。
  - 有料プランは月5ドルから（月1,000万リクエスト込み）。
  - 転送量（帯域）は課金なし。
- **今後の方向性**: Cloudflare Pagesは終了していませんが、新しい機能はWorkersに追加されています。公式の移行ガイドもあるので、**これから始めるならWorkersの静的アセットが無難**です。
- **メリット**
  - PHPやデータベースを公開しないので、攻撃される入口が非常に少ない。
  - DDoS対策、WAF、SSL証明書が標準で付く。
  - 世界中のCDNから配信されるので表示が速い。
  - GitHubと連携すれば、AIで修正 → push → 自動で公開、という流れにできる。AIを使った開発と特に相性が良い。
  - フォームなどが必要になっても、Workers、D1（データベース）、Turnstile（ボット対策）で対応できる。
- **デメリット**
  - 社内の担当者が画面から更新する仕組みはない。そのため、更新が必要ならCMS（記事を管理する仕組み）を別に組み合わせる必要がある。
  - Next.jsを動かすのは、Vercelに比べると少し癖がある（vinextやOpenNextといった変換ツールを使う必要がある）。
  - ドメインのDNS（ドメインと公開先をつなぐ設定）をCloudflareに移すと、メールの設定なども含めて移行作業が必要になる。

### C. Vercel

- **費用**【要確認・公式ページで確認推奨】
  - 無料のHobbyプランは**商用利用が禁止**。会社のサイトは対象外になる可能性が高い。
  - Proプランは**1人あたり月20ドル**で、使った量に応じて追加料金がかかる。
- **メリット**: Next.jsを作っている会社のサービスなので、Next.jsとの相性が最も良い。設定がほぼ不要。
- **デメリット**: 会社のサイトだと有料プランが必須。アクセスが急に増えると従量課金が膨らむおそれがある。

### D. Netlify

- **費用**【要確認】
  - 無料プランは月300クレジット制（ポイントのように使った分だけ減る方式）。
  - 有料はPersonal月9ドル、Pro月20ドル。
  - 1回公開するごとにクレジットを消費するので、頻繁に公開すると無料枠をすぐ使い切る。
- **メリット**
  - 無料プランでも商用利用できるとされる【要確認】。
  - フォーム機能が標準で付いている。
- **デメリット**
  - クレジット制のため、費用を予測しにくい。

### E. その他（参考）

- **AWS Amplify / S3＋CloudFront**: 社内ですでにAWSを使っているなら候補になる。設定は難しめ。
- **GitHub Pages**: 無料でシンプル。ただしサーバー側の処理は使えず、会社のサイトとしての運用には制約がある。
- **ヘッドレスCMS（microCMS など）**: 公開先ではなく記事を管理する仕組み。Cloudflareと組み合わせて「更新しやすさ」を補う。

## 5. おすすめの進め方

1. `johnan-app` をCloudflare Workersで公開し、まずは仮のURL（`*.workers.dev`）で確認する。
2. 本番のドメイン（またはサブドメイン）をつなぐ。DNSを移すかどうかは、メールへの影響を確認してから決める。
3. 更新が必要になったら、microCMSを入れるか、WordPressを記事管理だけに使う構成にする。
4. 既存のWordPressを残す場合は、プラグインを整理し、自動更新とWAFを有効にする。
